# Issue tracker

Runweft's optional durable issue tracker is GitHub Issues at
[1deat0r/runweft](https://github.com/1deat0r/runweft/issues). The current user task,
repository state, and local commit history are the normal context for routine work.

Create or use an Issue when it materially helps preserve a deferred or multi-session
backlog item, dependency, major feature or architecture discussion, external report,
or coordination record. Do not create an Issue for routine work that can be completed,
verified, reviewed, and committed in the current session. An Issue is not permission
to expand scope or begin proposed runtime work.

Matt Pocock skills that default to publishing every spec or ticket must follow this
repository policy: draft locally first, and publish to GitHub only when durable
tracking adds value or the user asks for it. Pull requests are not the default
request surface; they are optional for major, risky, external, concurrent, or
protection-sensitive work. When an Issue exists, fetch it with `gh issue view <n>`
and keep public content free of credentials, private user data, and vulnerability
details. Use `SECURITY.md` for private vulnerability reports.
