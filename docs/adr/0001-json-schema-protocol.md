# JSON Schema for the cross-language protocol

Status: Accepted and implemented locally for Ticket 01 after independent systems, security, and evaluation closure reviews (2026-09-29).

Use JSON Schema Draft 2020-12 as the single source for version 1.0 wire messages. Generate Rust bindings with quicktype-core 26.0.0 and TypeScript bindings with a small deterministic repository-local schema emitter. The quicktype TypeScript renderer overflows on the schema's legal recursive extension type; the local emitter preserves that recursive alias without another dependency. Validate inputs independently with Rust jsonschema 0.58.2 and TypeScript Ajv 8.20.0; generated types alone are not runtime validation. Strict envelopes reject unknown fields except bounded namespaced values inside the explicit extensions map. Unknown critical variants fail closed. Lifecycle, peer-role, and error policies have machine-readable sources and are checked against schema variants. The 50-case literal oracle is supplemented by exhaustive transition-edge checks and deterministic authority/action-binding tests.

The alternatives considered were Protocol Buffers, which would require deciding whether binary or JSON mapping is the actual wire format, and hand-maintained Rust/TypeScript types, which would duplicate the contract. The generator and validator versions are pinned by `package-lock.json` and `Cargo.lock`. Changing a locked version requires regenerating both bindings and passing the cross-language corpus. This decision includes exact numeric range checks, coordinator-only event ingress, fully fenced approval/reconciliation, safe extension values, and explicit sequence/deduplication semantics. It defines contracts and validation only; it does not authorize production execution or release.
